Top Tabs

Spectrum

The spectrum view shows spectra as a count histograms, retrieved from a connected device or loaded from a file. It can show several spectra combined in one plot or separately. This can be changed under Options -> Tabbed-/Combined Spectrum View.

Background spectra can be viewed as one the three following methods No background, Background overlay and background subtract. Background overlay shows the background spectrum overlaid on top of the main spectrum. Background subtract does channel wise subtraction of the background from the foreground spectrum, this is a hard background subtraction and will effect ROI calculations on the spectrum. Both Background overlay and background subtract only show values of count rate.

  1. Rest Zoom resets the zoom of the spectrum and locks the y-axis if unlocked.

  2. Unlock y-axis allows the y-axis to be zoomed independently and disables autoscaling.

  3. Log set the scale of the y-axis to logarithmic.

  4. CPS normalises the spectrum to the live time, or real time if live time is not available but real time is.

  5. Cursor toggles the spectrum cursor, see .

  6. Add ROI adds a customisable region of interest to the spectrum, see .

  7. Switch the use of background spectrum. Options are No background, Background overlay and background subtract. See the section above.

  8. Display for info from the cursor, see .

  9. The y-axis show either total counts or time normalised counts in units of .

  10. The x-axis always display energy in units of keV.

Regions of interest (ROI) are sub regions of the spectrum bounded in energy and are useful in the analysis of spectrum peaks. Spectrum peaks can in most cases be approximated with a Gaussian function and knowing the function parameters to describe is useful for many analyses. LuRaCs provides a method for fitting Gaussian functions to peaks inside ROIs and do so by default. These fits are required by other tools in the application. However, ROIs can also be configured to not perform fits, in these cases only the total ROIs counts are calculated.

  1. A ROI with one peak and a fitted Gaussian peak and linear background.

  2. Two merged ROIs that fit two Gaussian peaks on a shared quadratic background.

  3. The ROI editor for ’ROI_2’, see .

Spectrogram

A spectrogram allows time-series measurements to be conducted. A spectrogram stores data at specified time intervals and can be displayed in a waterfall plot. It is also the method LuRaCs uses for mobile measurements. If a GPS is connected the geolocation data provided is automatically stored in the spectrogram. These measurements can visualised on the embedded Map.

  1. Opens a dialog for starting a new spectrogram.

  2. Close the viewed spectrogram.

  3. Shortcut to the Data Store Spectrogram page, see section 1.7.

  4. Selector for currently loaded spectrograms. Status is shown to the left as [ACTIVE], [LOADED] or [PAUSED].

  5. Pause or Resume data collections, requires that the same instrument used collect the previous data to be connected.

  6. Options menu, see

  7. Current information stored in the spectrogram and information about the Time Selector if active.

  8. Count histogram. Shows either total accumulated spectrum upon loading a measured spectrogram, summed channel counts inside the Time Selector if active or counts in the latest row.

  9. ROI illustrated in the histogram, can be deleted with Mouse-2.

  10. Waterfall diagram of the spectrogram.

  11. Time Selector to study a specific time interval. Can be toggled in the options menu (6.).

  12. Break line, illustrates that the time between measured points exceeds the Time Interval. Can indicate a connection and caution should be taken to verify data integrity. Can be toggled in the options menu (6.).

  13. Y-axis displays the timestamps of when each row was measured.

  14. X-axis display spectrum energy if calibrated.

  15. Color slider for the waterfall diagram. Color map can be changed by clicking Mouse-2 on the gradient bar.

The spectrogram format is based around an SQLite database, see section [sec:file_spectrogram] for further details on the format. The following data is stored for each time point in the spectrogram:

  • Timestamp.

  • Average count rate measured since the last time point.

  • Average dose rate measured since the last time point.

  • Device temperature at the time the data is written.

  • Longitude at the time the data is written, if a GPS is available.

  • Latitude at the time the data is written, if a GPS is available.

  • Spectrum difference since the last written data point, stored as compressed binary.

  • Meta data, stored as a utf-8 encoded and zlib compressed json-string. Examples of stored metadata include extended GPS data.

Map

Loading a map enables viewing of geographic measurements made with a spectrogram and a GPS. Maps can be loaded from online API requiring an internet connection or loaded from a .pmtiles-file for offline use. Compatible APIs and files are offered by several vendors, the software QGis offers support for exporting .pmtiles from other formats using plugins.

Disclaimer

LuRaCs does not provide or distribute map data. Users are responsible for ensuring that any map data or tile services they use with LuRaCs are obtained and used in accordance with the applicable licenses, terms, and usage restrictions.

The map is rendered using Qt’s web engine making it a powerful but heavy tool. Using offline maps can use a lot of system memory since the server needs to cache tiles for a smooth view. Use a system with enough memory for this method. However, both the map and datapoints are rendered using GPU acceleration with WebGL allowing for 10 000s of points to be displayed without excessive stress on the system. For reference, a Raspberry Pi 5 with 8 GB of RAM can render a 1.4 GB map file without any stutter, total memory usage was approximately 2 GB.

  1. Options menu for loading maps and importing and exporting simple tracks.

  2. Longitude and Latitude of the cursor.

  3. Name of the loaded map.

  4. List of loaded spectrograms, if the selected contains no geolocation data no points are displayed.

  5. Selector for what data is shown. total Count Rate, Dose Rate or count rate inside a loaded ROI.

  6. Main map view.

  7. Color gradient selector for the track points and a histogram over measured values. Color map can be changed by clicking Mouse-2 on the gradient bar.

  8. Live data from the GPS.

  9. Current GPS position, always displayed as a white and blue circle.

Load a map

is done from Map Options -> Load Online/Offline Map. An offline map takes the form of a .pmltiles files and choosing this options prompts the selection of such a file. Choosing to load an online map prompts the entering of a URL to a tile serving API, possibly including an API key. The checkbox allows for saving the last used URL. If a personal API key is used be aware that URLs are saved unencrypted.

Spectrogram ROIs

Spectrogram ROIs differ from Spectrum ROIs in that do no curve fitting. When applied to a spectrogram they sum the counts from all the channels within their bounds and do so for every row in the spectrogram. The results are displayed in count rate, the number of counts are normalised to the save interval, for easier comparison if the recorded spectrograms use different save intervals.

  1. Plots over two spectrogram ROIs evaluated on two spectrograms.

  2. Calculation ROI

  3. Button for removing the calculation ROI

  4. Settings for the first spectrogram in the calculation ROI. The first combobox lists loaded spectrograms and the second selects the data, total count rate or count rate from a ROI.

  5. Mathematical operation used to compare the values, +, - or /.

  6. Settings for the second spectrogram in the calculation ROI. Setting identical to the first (4.).

  7. ROI names. Calculation ROIs currently only have a tag.

  8. ROI data in text form. Shown is the latest value and (mean+-std) calculated from the data shown in the plot.

For use in mobile measurements where several ROIs is monitored at the same time a ’Compact View’ can be used. This is enabled under View -> Spectrogram ROis -> Compact View. This strips everything except the y-ticks and the plot itself.

Calculation ROIs are plots calculated from the results of other ROIs. These perform element wise operations and do not account for differences in measurement parameters. Element 0 from ROI 0 is combined with Element 0 of ROI 1, regardless of measurement date or spectrogram save interval.

Isotopics

LuRaCs provides a library of data for a selection of common radionuclides and can be viewed in this tab. These can be used to draw reference lines for emissions in the spectrum plot. Most of the nuclide data is sourced from Laboratoire National Henri Becquerel, a few nuclides not provided by LNHB had be sourced from elsewhere. A citation is provided for each nuclide and full references can be found under Help -> Bibliography.

  1. Spectrum and gamma emission lines, drawn as solid lines. Line height corresponds to emission intensity,

  2. X-ray emission lines, drawn as dashed lines. Line height corresponds to emission intensity.

  3. Nuclide list, select nuclide with the checkbox to the left and change colour of the lines with the right coloured button.

  4. Information of the current clicked nuclide.

  5. Peak automation, see bellow.

Auto matching nuclides to ROIs is accomplished by using the centroid of a fitted peak and finding emission close in energy. The matching is weighted by the emission intensity so a strong emission will be chosen over a weak of they are the same distance from the peak centroid. By selecting nuclides the auto matching of nuclides to ROIs, including from using the button inside the ROI Editor, are limited emission from the selected nuclides. Using auto match nuclides against all possible candidates are often unreliable, especially if the energy calibration is imperfect.

The peak search is based on Savitzky-Golay Smoothing and the filter derivatives to compute peak candidates. These candidates are then filtered and the accepted peaks are added as ROIs. The length of the window in the Savitzky-Golay filter can be set in units of channels.

Console

Deconvolution

This tool does more than simply reducing the effect of energy resolution but will still be referred to as a deconvolution operation. Deconvolution in this sense is more similar to reconstruction as, like image reconstruction in nuclear medicine, it employs the ML-EM algorithm. By using a detector response matrix, most simply acquired using Mone Carlo-simulations, the effects of the detector resolution, scattering in the detector and other effects can be reduced. The response matrix represents the expected detector response to a photon emitted at a certain energy, see and section [sec:]

  1. The original Co-60 spectrum in blue and the deconvolved spectrum in orange.

  2. Control window for the deconvolution operation, see .

  3. The deconvolved spectrum is added as new spectrum, copying information from the original.

Efficiency

The intrinsic efficiency is an important detector property and describes the fraction of photons hitting the detector that is actually detected.

Resolution

The energy resolution describes how well the detector can resolve detected photons of different energies. A low resolution results in broad peaks which can cover smaller peaks, making them harder to detect.

  1. Fitted peaks from all loaded spectra and ROIs. A ROI without a fit can not be included. Unchecked entries will be ignored in the calculation.

  2. Instrument to be given the calculation result. Can be Unique or Generic.

  3. How the calculation results should be plotted. These do not affect the results, only the view.

  4. The resolution function, coefficients are in arbitrary units and not % (% = au * 100). The R2 value of the fitted function compared with the data points.

  5. Assign the calculation results to the instrument set in (2.).

Detector Connection & Control

Connecting detectors using the GUI is facilitated through a dialog for each type of connection, the are found under Detector -> Connect Bluetooth/USB/Network. Connecting to bluetooth and USB requires the application the scan for available devices, the serial number of the found devices are then displayed for selection.

Connecting the a network devices requires knowing the device IP and type beforehand. Connecting to network detectors have the unique option to use the detector as a GPS. This is primarily intended for the Ortec Detective X which has a built in GPS.

When connecting to serial GPS devices the application scans serial ports and lists suggestions but the port can also be entered manually. The baud rate is typically 4800 but a selection of other common rates are also presented.
