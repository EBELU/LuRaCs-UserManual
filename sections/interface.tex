\subsection{Top Tabs}
\subsubsection{Spectrum}
The spectrum view shows spectra as a count histograms, retrieved from a connected device or loaded from a file. It can show several spectra combined in one plot or separately. This can be changed under \texttt{Options -> Tabbed-/Combined Spectrum View}.


Background spectra can be viewed as one the three following methods \textit{No background}, \textit{Background overlay} and \textit{background subtract}. \textit{Background overlay} shows the background spectrum overlaid on top of the main spectrum. \textit{Background subtract} does channel wise subtraction of the background from the foreground spectrum, this is a hard background subtraction and will effect ROI calculations on the spectrum. Both \textit{Background overlay} and \textit{background subtract} only show values of count rate.

\textit{Regions of interest} (\textbf{ROI}) are sub regions of the spectrum bounded in energy and are useful in the analysis of spectrum peaks. Spectrum peaks can in most cases be approximated with a Gaussian function and knowing the function parameters to describe is useful for many analyses. LuRaCs provides a method for fitting Gaussian functions to peaks inside ROIs and do so by default. These fits are required by other tools in the application. However, ROIs can also be configured to not perform fits, in these cases only the total ROIs counts are calculated.

\subsubsection{Spectrogram}
A spectrogram allows time-series measurements to be conducted. A spectrogram stores data at specified time intervals and can be displayed in a waterfall plot. It is also the method LuRaCs uses for mobile measurements. If a GPS is connected the geolocation data provided is automatically stored in the spectrogram. These measurements can visualised on the embedded Map.

    \label{fig:spectrogram_view}

            \item Close the viewed spectrogram.

The spectrogram format is based around an SQLite database, see section \ref{sec:file_spectrogram} for further details on the format. The following data is stored for each time point in the spectrogram:

\begin{itemize}
    \item Timestamp.
    \item Average count rate measured since the last time point.
    \item Average dose rate measured since the last time point.
    \item Device temperature at the time the data is written.
    \item Longitude at the time the data is written, if a GPS is available.
    \item Latitude at the time the data is written, if a GPS is available.
    \item Spectrum difference since the last written data point, stored as compressed binary.
    \item Meta data, stored as a utf-8 encoded and zlib compressed json-string. Examples of stored metadata include extended GPS data.
\end{itemize}

\subsubsection{Map}
Loading a map enables viewing of geographic measurements made with a spectrogram and a GPS. Maps can be loaded from online API requiring an internet connection or loaded from a \textit{.pmtiles}-file for offline use. Compatible APIs and files are offered by several vendors, the software \textit{QGis} offers support for exporting \textit{.pmtiles} from other formats using plugins.

\paragraph{Disclaimer} LuRaCs does not provide or distribute map data. Users are responsible for ensuring that any map data or tile services they use with LuRaCs are obtained and used in accordance with the applicable licenses, terms, and usage restrictions.

The map is rendered using Qt's web engine making it a powerful but heavy tool. Using offline maps can use a lot of system memory since the server needs to cache tiles for a smooth view. Use a system with enough memory for this method. However, both the map and datapoints are rendered using GPU acceleration with WebGL allowing for 10 000s of points to be displayed without excessive stress on the system. For reference, a Raspberry Pi 5 with 8 GB of RAM can render a 1.4 GB map file without any stutter, total memory usage was approximately 2 GB.

\subsubsection{Spectrogram ROIs}
Spectrogram ROIs differ from Spectrum ROIs in that do no curve fitting. When applied to a spectrogram they sum the counts from all the channels within their bounds and do so for every row in the spectrogram. The results are displayed in count rate, the number of counts are normalised to the save interval, for easier comparison if the recorded spectrograms use different save intervals.

For use in mobile measurements where several ROIs is monitored at the same time a 'Compact Mode' can be used. This is enabled under \texttt{View -> Spectrogram ROis -> Compact Mode}. This strips everything except the y-ticks and the plot itself.

\textit{Calculation ROIs} are plots calculated from the results of other ROIs. \textbf{These perform element wise operations and do not account for differences in measurement parameters}. Element 0 from ROI 0 is combined with Element 0 of ROI 1, regardless of measurement date or spectrogram save interval.

\subsubsection{Isotopics}
LuRaCs provides a library of data for a selection of common radionuclides and can be viewed in this tab. These can be used to draw reference lines for emissions in the spectrum plot. Most of the nuclide data is sourced from \textit{Laboratoire National Henri Becquerel}, a few nuclides not provided by LNHB had be sourced from elsewhere. A citation is provided for each nuclide and full references can be found under \texttt{Help -> Bibliography}.

            \item X-ray emission lines, drawn as dashed lines. Line height corresponds to emission intensity.

Auto matching nuclides to ROIs is accomplished by using the centroid of a fitted peak and finding emission close in energy. The matching is weighted by the emission intensity so a strong emission will be chosen over a weak of they are the same distance from the peak centroid. By selecting nuclides the auto matching of nuclides to ROIs, including from using the button inside the \textit{ROI Editor}, are limited emission from the selected nuclides. Using auto match nuclides against all possible candidates are often unreliable, especially if the energy calibration is imperfect. 

The peak search is based on Savitzky-Golay Smoothing and the filter derivatives to compute peak candidates. These candidates are then filtered and the accepted peaks are added as ROIs. The length of the window in the Savitzky-Golay filter can be set in units of channels.

The console allows for entering text commands to control the application and running scripts for basic automation. See \autoref{subsec:cli} for information on available commands and their usage.

\subsubsection{Deconvolution}
This tool does more than simply reducing the effect of energy resolution but will still be referred to as a deconvolution operation. Deconvolution in this sense is more similar to reconstruction as, like image reconstruction in nuclear medicine, it employs the ML-EM algorithm. By using a detector response matrix, most simply acquired using Mone Carlo-simulations, the effects of the detector resolution, scattering in the detector and other effects can be reduced. The response matrix represents the expected detector response to a photon emitted at a certain energy, see \autoref{tab:response_matrix_schema} and section \ref{sec:}

\subsubsection{Efficiency}
The intrinsic efficiency is an important detector property and describes the fraction of photons hitting the detector that is actually detected.

\subsubsection{Resolution}
The energy resolution describes how well the detector can resolve detected photons of different energies. A low resolution results in broad peaks which can cover smaller peaks, making them harder to detect.

\begin{figure}[H]
    \centering

    \label{fig:gtools_resolution}

    \begin{flushleft}
        \begin{enumerate}
            \item Fitted peaks from all loaded spectra and ROIs. A ROI without a fit can not be included. Unchecked entries will be ignored in the calculation.
            \item Instrument to be given the calculation result. Can be Unique or Generic.
            \item How the calculation results should be plotted. These do not affect the results, only the view.
            \item The resolution function, coefficients are in arbitrary units and not \% (\% = au * 100). The $R^2$ value of the fitted function compared with the data points.

\subsection{Command Line Interface (CLI)}\label{subsec:cli}

\subsection{Detector Connection \& Control}
Connecting detectors using the GUI is facilitated through a dialog for each type of connection, the are found under \texttt{Detector -> Connect Bluetooth/USB/Network}. Connecting to bluetooth and USB requires the application the scan for available devices, the serial number of the found devices are then displayed for selection.

Connecting the a network devices requires knowing the device IP and type beforehand. Connecting to network detectors have the unique option to use the detector as a GPS. This is primarily intended for the Ortec Detective X which has a built in GPS.

When connecting to serial GPS devices the application scans serial ports and lists suggestions but the port can also be entered manually. The baud rate is typically 4800 but a selection of other common rates are also presented.

\subsection{Data Store}\label{sec:data_store}
The \textit{Data Store} allows for saving data objects in the application it self for easy access. It also allows for limited editing of previously saved objects. It contains the following object types \textit{Spectra}, \textit{Spectrograms}, \textit{ROIs}, \textit{Unique Instruments} and \textit{Generic Instruments}. 

All data items saved in the Data Store can be exported to a single zip-file with \texttt{File -> Export Data Store}. Such a file can be imported with \texttt{File -> Import Data Store}.
